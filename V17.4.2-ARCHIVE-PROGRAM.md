# V17.4.2 — archive daily program loading

The production daily program took about 26 seconds for 11 city pages on
2026-09-30. Menu 8 aborted it after 20 seconds, then repeated the same whole-day
request when listing cities, finding horses, and updating histories.

Menu 8 now reuses the already loaded city's complete race list, including TJK
horse IDs and origin links. A selected city's list is never treated as the
whole-day program. Dates and city provenance are checked; empty race skeletons
are fetched again. The main page's full official response is also retained for
all four archive tabs.

`/api/tjk-program?date=…&catalog=1` retrieves just the city catalog.
`&cityId=…` retrieves only that city's official race page. Existing whole-day
requests preserve their response format and use three city workers. Every TJK
request, including reading its response body, has a 12-second limit.

Program requests are deduplicated and successful results cached for five minutes
in memory. “Günlük Programı Bul” explicitly refreshes the catalog and invalidates
the corresponding cached horse lists. Failed or partial programs are not cached
as successful lists. Menu timeouts allow 30 seconds for a city and 65 seconds
for a whole day; ordinary horse history and origin download limits are unchanged.

The production build injects the program loader before the legacy runtime,
captures the main page's official payload at `getCurrentRaceList`, clears old
horses while changing cities, and stamps loaded date/city provenance. All nine
column coupon methods and the condition-aware tenth method remain intact.

Validation covers offline reuse, reload recovery, date/city boundaries, explicit
refresh, failed-request retries, partial programs, bounded city concurrency,
actual Menu 8 button actions and archive JSON writes in the browser.
